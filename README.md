# dsh-openai-codex-oauth

Вход в OpenAI Codex через подписку ChatGPT Plus/Pro по OAuth для DeepSeek Harness — без API-ключа. После входа модели, доступные вашей подписке, появляются в выборщике моделей группой «OpenAI Codex (подписка)». Помимо интерактивного входа, хранения учётных данных и автоматического обновления токена плагин показывает квоты подписки (`/codex-usage`), регистрирует провайдер веб-поиска на web-шине харнесса и инструмент `generate_image` для генерации изображений через подписку.

Проект — форк [`dyuan311/dsh-openai-codex-oauth`](https://github.com/dyuan311/dsh-openai-codex-oauth) (MIT), адаптированный под DSH `0.1.0-rc.5` и русифицированный; вспомогательные вызовы бэкенда портированы из [`WNJXYK/dsh-codex-oauth`](https://github.com/WNJXYK/dsh-codex-oauth) (MIT, см. [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)). Китайская документация upstream сохранена в [README.zh-CN.md](README.zh-CN.md).

## Требования

- DSH-форк на базе `0.1.0-rc.5` с адаптером `llm-pi-ai` в базовом бандле.
- Node.js `^22.19.0 || >=24`.
- Подписка ChatGPT Plus/Pro с доступом к Codex. Отдельный OpenAI API-ключ не нужен.
- Для входа через браузер — браузер на машине харнесса и свободный локальный порт `1455`.

## Установка

```sh
dsh plugin --profile web add github:icas711/dsh-openai-codex-oauth
```

Затем перезапустите `dsh web`. Каталог `lib/` собран и закоммичен в репозиторий, поэтому при установке build-скрипты не выполняются — плагин готов к работе сразу после загрузки.

## Вход

В интерфейсе харнесса выполните:

```text
/codex-login
```

Команда спросит способ входа:

- **«Через браузер»** — откроется страница авторизации OpenAI в браузере на машине харнесса; после входа колбэк придёт на `localhost:1455`.
- **«Код устройства»** — для headless-серверов и окружений без графики: откройте `auth.openai.com/codex/device` с любого устройства и введите показанный код.

Если браузер находится на другой машине, удобен путь **«вставка callback URL»**: после входа OpenAI перенаправит браузер на `localhost:1455` (страница покажет ошибку соединения — это нормально), скопируйте полный адрес из адресной строки и вставьте его в поле вопроса — плагин завершит вход по этому адресу.

Сокращения:

```text
/codex-login device   # сразу поток с кодом устройства
/codex-status         # состояние входа и срок действия access-токена
/codex-logout         # удалить учётные данные
/codex-usage          # квота подписки (окна 5 ч / неделя)
/codex-usage refresh  # квота без кэша (кулдаун по умолчанию 30 с)
```

## Квоты подписки

Команда `/codex-usage` запрашивает `chatgpt.com/backend-api/wham/usage` и показывает план, заполненность 5-часового и недельного окон, время сброса и сброс-кредиты — только те поля, которые реально вернул бэкенд. Ответ кэшируется на `usageCacheMs` миллисекунд (по умолчанию 30 000); `refresh` обходит кэш. Ошибки не маскируются: любой не-2xx ответ виден как есть, с HTTP-статусом.

Инструмент `codex_usage` (тот же данные, но для модели) по умолчанию выключен — включайте конфигом `usageTool: true` после того, как убедитесь, что живой ответ бэкенда стабилен:

```yaml
    usageTool: true
```

## Веб-поиск через подписку

Плагин регистрирует на web-шине харнесса провайдер `openai-codex`: запрос уходит на Responses-эндпоинт Codex с принудительным hosted-инструментом `web_search`, ответ ассистента и источники (URL-цитаты и результаты поиска) отображаются в стандартный словарь шины — инструмент `web_search` харнесса работает без доработок.

Провайдер не занимает выбор безусловно. Когда он один пригоден (есть вход, других провайдеров нет) — шина выберет его автоматически; иначе включите его штатной настройкой:

- в настройках профиля (`cordis.yml`): `web.searchProvider: openai-codex` (или переменная окружения `DSH_WEB_SEARCH_PROVIDER=openai-codex`);
- или через раздел настроек `web` в интерфейсе.

Отключается конфигом `searchEnabled: false`. Модель hosted-поиска — `searchModel` (по умолчанию `gpt-5.6-sol` из каталога pi-ai 0.82.1).

## Генерация изображений

Плагин регистрирует инструмент `generate_image` (модель видит его в своём наборе инструментов): запрос уходит на Responses-эндпоинт Codex с инструментом `image_generation`, готовый файл сохраняется в хранилище вложений харнесса и показывается штатной карточкой инструмента — отдельные права или клиентские доработки не нужны. Параметры: `prompt`, `size` (`1024x1024`, `1536x1024`, `1024x1536`), `quality` (`low`/`medium`/`high`), `background` (`auto`/`opaque`). Модель — `imageModel` (по умолчанию `gpt-5.6-sol`); отключение — `imageEnabled: false`.

Для работы нужны сервисы `tools` и `attachments` базового бандла; если их нет, плагин пишет об этом в лог и продолжает работу.

## Как это работает

В веб-интерфейсе плагин определяет владельца сессии и хранит учётные данные **лично**: полный OAuth-credential и access-токен пишутся в личное хранилище пользователя (`~/.dsh/web-user-credentials/<логин>.yaml`) под ссылками `OPENAI_CODEX_OAUTH_CREDENTIAL` и `OPENAI_CODEX_ACCESS_TOKEN`. Каждому веб-пользователю — свой `/codex-login` и свой ChatGPT-аккаунт; маршруты сессий с владельцем читают ключ строго из личного хранилища. Вне веб-сессий (консоль, агентные запуски без владельца) плагин работает с общим хранилищем харнесса (`~/.dsh/.credentials.yaml`). Перед истечением срока токен обновляется автоматически — за `refreshBeforeMs` миллисекунд (по умолчанию 300 000, то есть 5 минут).

Модели предоставляются встроенным провайдером `openai-codex` адаптера `llm-pi-ai`: патч в [cordis.patch.yml](cordis.patch.yml) включает его в бандл и настраивает чтение access-токена из хранилища учётных данных. Команды `/codex-status` и `/codex-login` сообщают, каким хранилищем они пользовались: «личное хранилище (<логин>)» или «общее хранилище харнесса». Ручное значение `OPENAI_CODEX_ACCESS_TOKEN`, сохранённое на странице «Настройки → Модели», доверяется как есть — но оно обязано быть именно access-токеном (JWT) подписки, а не API-ключом `sk-…`: у API-ключа нет account id, и запрос падает с ошибкой «Failed to extract accountId from token».

Квоты, веб-поиск и генерация изображений ходят напрямую в бэкенд Codex тем же access-токеном: идентификатор аккаунта достаётся из JWT, заголовок `originator` по умолчанию `pi` — тот же, что отправляет pi-ai в запросах этого харнесса (маскировки под официальный клиент нет, значение меняется конфигом `originator`).

Конфиг-поля плагина (значения по умолчанию):

```yaml
- id: openai-codex-oauth
  name: dsh-openai-codex-oauth
  config:
    oauthCredentialRef: OPENAI_CODEX_OAUTH_CREDENTIAL
    refreshBeforeMs: 300000
    responsesUrl: https://chatgpt.com/backend-api/codex/responses
    usageUrl: https://chatgpt.com/backend-api/wham/usage
    usageCacheMs: 30000
    usageTool: false        # инструмент codex_usage — после проверки живого ответа
    searchEnabled: true     # провайдер веб-поиска openai-codex на ctx.web
    searchModel: gpt-5.6-sol
    imageEnabled: true      # инструмент generate_image
    imageModel: gpt-5.6-sol
    originator: pi
```

## Ограничения и риски

- Это неофициальная интеграция поверх закрытых эндпоинтов Codex (`codex/responses`, `wham/usage`). OpenAI может изменить протокол или ограничить доступ — тогда потребуется обновление плагина или `pi-ai`. Плагин не выдаёт себя за официальный клиент: `originator: pi`, user-agent семейства pi-ai.
- OAuth-токены дают доступ к вашему аккаунту OpenAI. Не публикуйте их в issue, логах или конфигах; храните файл учётных данных в секрете.
- Вход по коду устройства может быть отключён на стороне OpenAI — в этом случае используйте вход через браузер или вставку callback URL.
- Web-шина харнесса не передаёт контекст сессии в провайдер поиска, поэтому провайдер определяет область учётных данных по последней сессии, начавшей запрос к модели. При одновременных ходах разных веб-пользователей область может перепутаться (команда `/codex-usage` и инструменты `generate_image`/`codex_usage` знают свою сессию точно). Поиск и генерация изображений расходуют квоту подписки.
- Схема ответа `wham/usage` не задокументирована OpenAI; нормализация терпит альтернативные имена полей, но при изменении бэкенда поля могут пропасть — плагин честно пишет «бэкенд не вернул …» вместо выдуманных значений.
- Статусы фаз: вход/модели проверены на живом аккаунте; квоты, веб-поиск и генерация изображений реализованы по спецификации из `WNJXYK/dsh-codex-oauth` и ждут живой проверки (см. план работ в репозитории форка).

## Разработка

```sh
corepack pnpm install
corepack pnpm build   # компиляция src/ -> lib/
corepack pnpm test    # модульные тесты (vitest)
```

Каталог `lib/` коммитится в репозиторий: установщик плагина не запускает сборку. Публикация изменений — через git_sync воркспейса в `icas711/dsh-openai-codex-oauth`.
